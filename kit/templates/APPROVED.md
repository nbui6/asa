# Approved sketches

**One row per drawing the Boss has actually said yes to.** Nothing else belongs here — not a
review, not a persona verdict, not a sketch that was sent and never answered.

> **Why this file exists.** Approval used to happen in a conversation and live in a chat scroll.
> On 2026-09-04 a screen was built twice against a drawing that could not be produced when asked
> for, because nothing recorded **which image, at which version, approved on which date, covering
> which screen.** *`KIT-LOG.md`, "shown is not saved".*

**Both formats, always.** A `.png` can only be redrawn. The source can be re-rendered.

## The rules

1. **A row is added the moment a yes arrives, and not before.** *"Sent, awaiting an answer"* is not
   a row in this file; it is a line in the round note.
2. **Both paths must resolve.** `check-refs.ps1` checks that, so nobody has to remember.
3. **Superseded rows stay**, with the superseding row underneath and a note saying what replaced
   it. **A design's history is the point** — an argument about "what we agreed" is unanswerable
   without it.
4. **The last column is the one that gets used.** One sentence a builder can hold in their head
   while reading the image: *"a quiet typographic list — no app bar, no cards, status as a small
   inline pill, dates humanised and right-aligned."* Write it when the approval arrives, while it
   is still obvious.
